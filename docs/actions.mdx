# Actions Reference

Every CodeVideo project is a list of actions. Each action is a `{ "name": "...", "value": "..." }` object: the name says what happens, the value says what to do it with. Send a list of them to the API (see the [Quick Start](/)) or render them locally with the [CLI](/cli).

Use the table of contents to jump to a domain, or link to an action directly, e.g. [`/actions#editor-type`](#editor-type).

### TypeScript squiggles

Squiggles are off unless you ask for them, so existing projects render exactly as before. Turn them on for the whole video with the `isDiagnosticsVisible` option, or for part of a lesson with `editor-show-diagnostics` and `editor-hide-diagnostics`. To show an error's message the way VS Code does, move the mouse onto it with [`mouse-move-editor-diagnostic`](#mouse-move-editor-diagnostic). Its value is the active file's path, line and column, 1-based and separated by colons:

```json
{ "name": "mouse-move-editor-diagnostic", "value": "src/generics/generics.ts:62:29" }
```

The hover stays open through narration and waits, so the narration can read the message. Any other action closes it.

- **When they update.** Squiggles are recomputed when an action that changed a file finishes, not on every keystroke. While `editor-type` runs, existing squiggles move with the text, and new ones appear when the typing ends.
- **What checks the code.** TypeScript 5.4.5, the release Monaco ships, with settings close to a Create React App `tsconfig.json` (`strict`, `jsx: react-jsx`, the DOM libraries). `.ts` and `.tsx` files get type errors; `.js` and `.jsx` files get syntax errors only. The MCP's `codevideo_compile_lesson` uses the same release and settings, so it reports what a video shows.
- **npm packages.** Projects carry no `node_modules`, so every package a file imports gets an untyped stand-in: `react`, `react-dom/client` or any other import never goes red. Names you take from a package still work as types (`ReactNode`, `React.FC<Props>`) and with type arguments (`useState<string>()`). CSS and image imports resolve as they do in Create React App.
- **Known limits.** A callback passed to something an untyped package returned, such as `axios.get('/u').then((response) => ...)`, has no type for its parameters, so `strict` flags them as implicit `any`; give the parameter a type. Code written for an older TypeScript can show errors that release didn't, for example `Object.keys(value)` on an unconstrained generic since TypeScript 4.8.
